# Регламент реакции оператора на тревогу

Статус: проект для согласования. Он не отменяет штатные инструкции, ПЛК и
защиты оборудования.

## Последовательность действий

1. **Подтвердить получение в течение 5 минут.** Записать ID тревоги, время,
   агрегат и значение score. Не отключать защиту и не менять уставки.
2. **Проверить контекст.** Убедиться, что агрегат работает; посмотреть TP2,
   TP3, давление резервуаров, температуру масла, ток двигателя и активные
   дискретные сигналы.
3. **Осмотреть по действующей инструкции.** Проверить доступные соединения
   пневмоконтура, необычный шум, падение давления и утечку. Соблюдать правила
   допуска и охраны труда.
4. **Эскалировать.** При подтверждённых признаках вызвать ответственного
   механика/инженера. Контролируемую остановку выполняет только уполномоченный
   сотрудник по локальному регламенту.
5. **Закрыть обратную связь.** В интерфейсе отметить, был ли фактический отказ,
   и оставить запись в журнале обслуживания.

## Приоритет

| Уровень | Условие | Действие |
| --- | --- | --- |
| Наблюдение | единичная тревога, штатные показания | подтвердить, проверить контекст |
| Повторная | повтор после cooldown или рост score | инженерная проверка в текущую смену |
| Критическая | тревога плюс штатная защита/резкое падение давления | действовать по аварийному регламенту площадки |

## Маршрут уведомления

Сервис отправляет `POST` на `ALERT_WEBHOOK_URL` только при создании новой
тревоги. Повторные строки подавляются 15 минут для одного агрегата.

```json
{
  "event": "compressor_condition_alert",
  "prediction_id": "uuid",
  "machine_id": "METRO-APU-01",
  "risk": 0.42,
  "threshold": 0.001,
  "recommended_action": "Acknowledge, inspect pressure circuit, and follow the operator playbook."
}
```

Перед пилотом владелец производства должен заполнить роли, канал, время
реакции и правила остановки в форме экспертной проверки.
