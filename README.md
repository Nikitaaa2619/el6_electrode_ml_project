# EL6 / Electrode Factory — ML Predictive Maintenance

Учебный проект для портфолио Data Scientist / ML Engineer. Модель оценивает
риск перегрева оборудования в следующие 10 минут по текущей телеметрии.

## Важное ограничение

Все данные в проекте **синтетические**. Это не телеметрия ЭЛ6/НОВЭЗ, не
реальные производственные уставки и не подтверждённая модель оборудования.
ML-модель не управляет станком и не заменяет штатную защиту или ПЛК.

Целевая колонка `overheat_next_10min` — искусственная метка риска, рассчитанная
генератором из будущей температуры и дополнительных сигналов.

## Как устроен проект

```text
src/generate_data.py  -> data/telemetry.csv
data/telemetry.csv    -> src/train.py -> models/model.joblib
models/model.joblib   -> app/main.py  -> POST /predict
Dockerfile            -> Docker-образ с API и моделью
```

CSV и обученная модель создаются локально и не хранятся в Git.

## Локальный запуск

Рекомендуемая версия — Python 3.12.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
python src/generate_data.py
python src/train.py
python -m uvicorn app.main:app --reload
```

После запуска доступны:

- API: http://127.0.0.1:8000/
- интерактивная документация: http://127.0.0.1:8000/docs

## Проверенный baseline

Результаты получены 29 сентября 2026 года на временном разделении 80/20 с
10-минутным зазором между обучающей и тестовой частями:

| Метрика | Значение |
| --- | ---: |
| Accuracy | 0.896 |
| Precision, класс риска | 0.469 |
| Recall, класс риска | 0.864 |
| F1, класс риска | 0.608 |
| ROC-AUC | 0.953 |
| Average precision (PR-AUC в выводе) | 0.684 |

Матрица ошибок: 9752 верных нормальных состояния, 1094 ложные тревоги,
152 пропущенных случая риска и 966 верно найденных случаев риска. Доля риска
составляет 10,20% в обучении и 9,35% в тесте. Accuracy простой стратегии
«всегда нет риска» равна 0.907, поэтому для этой задачи важнее рассматривать
recall, precision и PR-AUC вместе, а не одну accuracy.

Эти результаты описывают только искусственные данные текущего генератора и не
доказывают качество модели на реальном производстве.

## Запуск в Docker

Сначала нужно создать данные и обучить модель локально, чтобы появился файл
`models/model.joblib`. Затем:

```bash
docker build -t el6-electrode-ml .
docker run --rm -p 127.0.0.1:8000:8000 el6-electrode-ml
```

После запуска документация снова доступна по адресу
http://127.0.0.1:8000/docs. `Control+C` останавливает контейнер, а `--rm`
удаляет его остановленный экземпляр; Docker-образ остаётся.

## Ограничения текущей версии

- Порог предупреждения 0.5 пока не подбирался на отдельной валидационной части.
- Даже улучшенный генератор остаётся упрощённой учебной симуляцией и не
  воспроизводит физику реального производственного оборудования.
